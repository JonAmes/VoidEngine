# Phase 3 — Mini render framework
Status: in progress (started 2026-11-08)

Shaped by: **#6/#3-AGENTS** (passes write render targets, a Presenter presents — never "the backbuffer"), **#37** (Vulkan 1.3 floor), **#35** (ctest gfx on forced lavapipe; strict byte-exact goldens stay Linux/lavapipe-only), **#34** (RH Y-up −Z fwd — the rig frame), **#2** (off-axis asymmetric per-eye projections are first-class, not a retrofit), **#14** (Blender conventions: node-name keys, cook-side MikkTSpace tangent bake, cooklet-owned flags), **#13** (everything gfx loads by content ID through the manifest), **#15/#16** (immediate-mode debug UI rendering into a target list + world-space canvas; its widget layer is the toolkit for every editor panel), **#38** (OS-neutral C++23 in every new TU).

Existing seams this phase builds on (Phase 2): `gfx/instance|device|frame_sync|presenter(+offscreen, +wsi)|shader_module`, cooked SHDR/TEX0/MESH/MAT0 + manifest (`core/cooked.h`), strict validation messenger, golden harness (`tests/gfx/gfx_golden`, `VE_GOLDEN_UPDATE=1`). Known gaps this phase closes: MESH payload ships pos/nrm/uv but **no tangents** (#14 requires cook-side bake); MAT0 has **no texture refs** and the cooklet never emits glb→texture manifest deps (`glb.cpp` literally defers this).

**Deferred design questions (user said: start, questions later).** Defaults below are what tasks assume; overriding one = a follow-up box, not a block:
- Q1: new passes use **VK1.3 dynamic rendering** (no legacy VkRenderPass objects) — #37 lists it as a 1.3 core feature.
- Q2: tangent bake **bumps MESH 0.8→0.9 in place** (goldens regen) rather than a new fourcc.
- Q3: test/slice font = a freely-licensed system TTF (DejaVu Sans) vendored into `assets/fonts/`, license line in docs.
- Q4: the stereo done-when renders **one wide RT with two eye viewports** (also proves per-eye viewport flow), goldens per eye.
- Q5: per-material params live in a **UBO indexed by material**, per-draw data in push constants.
