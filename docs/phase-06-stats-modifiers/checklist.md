## Notes
- Precision split (AGENTS rule 5 + PLAN): StatsSet attr values are **fp32** ("stats" class); reservoir *state* is fp64 sim state (propellant drain must hit `force·t/Isp` hand-exactly; fp32 accumulation over 36k ticks would not).
- "Self-modifying cycles rejected by design, not debugged" = type-level: modifiers target attr keys only; no modifier→modifier edges exist in the data model, so cycles are unrepresentable. Assert it, don't detect it.
- Determinism everywhere: ordered containers, (tick, seq) event order, recompute-on-read dirty flags must never change results vs full recompute (property test in 6.4/6.5).
- Phase 5 seams consumed here: 5.11 occupancy (occupant-stats stack was explicitly deferred to Phase 6), 5.4 attr keys incl. `power.supply/draw`, DEF0 wire table (5.9b), mount tags (5.11), function-zero = a modifier that zeroes a "function" attribute; dark-not-dead convention continues.
- Explicitly NOT this phase: combat resolution itself (Phase 9 uses this machinery), target-selection/resolution layer for use-events (game-side, later), market/lanes authored defs cooking (Phase 8 map data — P6 tests build market state in-memory from params), scrubber render-pass integration beyond the imgui core widgets, EVA suit reservoir instances (Phase 7 — the primitive lands here).
