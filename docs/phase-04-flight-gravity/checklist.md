**Design questions Q1–Q6 below: all defaults ratified by the user 2026-11-09** (Q1/Q2/Q3 + world-def posture recorded as decision #45a-d; Q4/Q5/Q6 stand as checklist defaults).
- Q1: canonical fixed tick = **1/60 s**; the sim advances by integer tick counts (`int64_t`), never float seconds or wall clock. Time compression (P8) resamples on top later. (#45a)
- Q2: sim attitude is **fp64**: Phase 1's templated `quat<T>`/`mat4<T>` already provide `dquat`/`dmat4` — task 4.2 pins the untested double surface with tests. `dmat3` NOT added: diagonal principal-axis inertia (#45b) is dvec3 algebra; full tensors are Phase 5. fp32 `quatf` stays render/stats-only.
- Q3: rails are **circular, coplanar** (parent's XZ plane, Y-up); parent chain bottoms out at a static root anchor. Eccentricity/inclination are later *data*, not Phase 4 code.
- Q4: well profile: |g| = g_surface constant over [surface_radius, taper_start], then a C¹ quintic-smoothstep ramp to 0 at well_radius (zero slope at both ends — the imperceptible-edge blend *is* the feel); `taper_start` authored per body. In overlap shells the accelerations crossfade by a smoothstep weight of the two fields.
- Q5: replay/state hash = hand-rolled **FNV-1a 64** over raw fp64 bit patterns (tick + state), zero new deps; replay logs store *commands* per tick, not states (scrubber's state records are Phase 6's shape).
- Q6: assist controller gains are **hand-authored structs in tests**; the attribute-key declaration rides Phase 5/6 untouched.
