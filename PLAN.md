# Void Engine — Build Plan

**Goal:** A from-scratch C++ game engine whose first (and driving) project is an **arcade space sim** — Newtonian flight with assist toggles, arcade gravity wells (Babylon 5 / Battlecruiser school, no orbital-mechanics homework), hull + hardpoints ship designer, **one RPG stats system shared by player pilots, NPCs, and ships**, hybrid laser/ballistic combat with shields + component damage, huge-scale rendering — with **first-class VR output and a headless Linux test story from day one**. The journey is the point: every phase must compile, run, and be testable before moving on.

**Machine check (verified 2026-11-06):**
- g++ 15.2 (C++23/25 ready) ✅
- RTX 3090 + Quadro P5000 (Vulkan-capable; 3090 is a comfortable VR target) ✅
- Missing: cmake, ninja, Vulkan SDK/headers, SDL2/GLFW, OpenXR loader → **Phase 0 installs**

---

## Architecture decisions up front (these shape everything)

1. **C++23, CMake + Ninja, per-module static libs.** vcpkg/FetchContent only for: GLFW (window/input), Volk (Vulkan loader), OpenXR-SDK (loader only), stb, doctest, miniaudio (audio device+mixer, user-approved decision #32a), Tracy (profiler, user-approved 2026-11-07 as 7th dep). Everything else hand-rolled — that's the learning.
2. **Hand-rolled math library first.** `vec3f/mat4f/quatf` (fp32 for rendering) **plus fp64 position types** (`dvec3`). You cannot retrofit double precision later. The projection math must support **off-axis asymmetric frustums from day one** — VR eye projections are asymmetric; that's a Phase 1 feature, not a Phase 10 retrofit.
3. **Floating-origin world.** The camera rig is always at the origin; all world positions are offsets from it. This + fp64 sim positions is the single most important space-game decision (see Valve's moving-origin paper). Arcade physics removes the orbital math, not the scale problem — planet-to-planet distances still demand this.
4. **Simulation is headless and deterministic.** `core/` has zero rendering/windowing/XR dependencies. Unit-testable against known flight-model numbers, runs on a server someday (multiplayer later), and lets you build the flight/gravity core before the renderer is finished.
5. **Vulkan, not OpenGL.** 2026-only choice for learning modern engines. Brutal up front; use Volk to skip loader pain. Keep the renderer behind a thin `gfx/` interface so your future self can swap backends.
6. **Presentation is an abstraction, never assumed.** Render passes produce *render targets*; a `Presenter` consumes them: desktop swapchain, or XR swapchain images owned by the OpenXR runtime. Nothing may assume "the backbuffer", a fixed aspect ratio, or a single camera. This one seam is what makes VR an option instead of a rewrite.
7. **VR = OpenXR.** The Linux-native answer: SteamVR (Index/Quest via Link/WiRVR) or Monado (fully open, native Linux). No headset or even SteamVR needed for development — everything before real-hardware bring-up runs against a **mock XR runtime** (see Test tiers). Constraints baked in early: per-eye view rendering (single-pass instanced — cheap desktop-side too), runtime-chosen resolution scale + recommended FOVs consumed rather than assumed, 90 Hz budget for VR mode, and world-space (diegetic) UI because a fixed screen HUD doesn't exist in VR — which fits the genre perfectly: **cockpit-first is the native VR scene**, and cockpit-locked views are the most comfortable VR there is.
8. **ECS, but pragmatic.** Archetype-lite: entity + component arrays + systems in a fixed update order. Don't chase EnTT purity; chase cache-friendly iteration over the hot systems (thrust, assist controllers, LOD culling).
9. **Headless-first testing.** `ctest` must pass with no `$DISPLAY`, no compositor, no headset — over SSH, on this box, forever. Three tiers below. **Every phase's "Done when" must be satisfiable headless.**
10. **Arcade physics, hand-rolled (user decision):** gravity = arcade wells (surface "down" near a planet, blending to micro-gravity at well edge, nothing in deep space); flight = Newtonian drift with **toggleable assist controllers** (stabilizer, air-brake, auto-level); ships = **hull + hardpoints**, no free-form stacking. No Kepler elements, no SOI patching, no patched conics, no Δv planner. No physics middleware (Jolt/PhysX) — contact physics is part of the learning journey.
11. **One stats system for player, NPCs, and ships — engine machinery vs game content (user decision).** The engine (`core/`) ships only the framework: sparse tagged attributes, source-tagged modifier stacks with deterministic ordered aggregation, hierarchical gameplay tags, effects/conditions, and an attribute-change event bus. **Which stats exist is cooked data, never engine code** — the engine has no idea what "Piloting" means. Player pilots, NPC pilots, and ships all use the *same* `StatsSet` component — no special-cased player schema — so AI reads exactly the same data the player does, and pilot skill modifies ship stats through the *same* crew-seat → ship modifier linkage as mounted equipment. Stats state is part of deterministic sim state (hashed in replay tests) so a future server-authoritative multiplayer can trust it.
12. **Combat spec (user decision):** **Hybrid weapons** — instant-hit lasers/beams + physical projectile guns + unguided shells/rockets with real Newtonian ballistics (Elite/Free-Space school: drift makes aiming a skill; shells fall in gravity wells like everything else). **Defense** — regenerating shields soak first, then **per-component health**: components go *offline* (zeroed by modifiers, never destroyed), dock repair restores them — hardpoint loadouts stay meaningful. **Aiming** — the targeting computer is a **toggleable assist**, same philosophy as flight assists: free-aim base, assist adds lead/deflection reticle, range/closure readout, and optional rocket designation assist; pilot stats scale assist quality. **Slice AI** — one hostile faction, FSM pilots (patrol / engage / disengage / withdraw) running on the same assists + stats, aggression from stats, faction reputation as gameplay tags. Everything combat is `game/` data riding the Phase 6 effects system (damage = effects); the engine contributes only swept-collision and prediction primitives.
13. **Content ingestion pipeline (user requirement; plan defaults the user may override):** All content flows one way: human-editable source in `assets/` → **cooklet** (`tools/cook`) → deterministic binary units in `cooked/`. The runtime parses **only cooked data** — zero text parsing in the engine. Authoring format defaults to **TOML** for definitions (diffable, boring) + standard formats for binaries (GLTF, PNG, GLSL). One cooked envelope for everything: magic + format version + payload; units are **self-contained and independently loadable** — that's what makes cooked-data hot-reload and mod packs (Phase 12) a loader change, not a format change. A **manifest** (`manifest.bin`) maps stable content IDs (deterministic relative paths) → cooked blobs + a dependency graph (mesh→texture→material), so renames never break references. The cooklet resolves cross-references and **fails the cook** on dangling ones — you learn about a missing texture at cook time, not render time. Re-cooking is **incremental by content hash**, and cooking is deterministic: same inputs ⇒ byte-identical outputs (golden-tested, Tier 1). Content types: **models** (.glb → cooked mesh/material blobs), **textures** (PNG → cooked mip/layout), **fonts** (TTF → cooked glyph atlas via stb_truetype, per decision #15), **shaders** (GLSL → SPIR-V at cook time), **maps** — hybrid: authored system/planet definitions (bodies + gravity wells + stations + POIs + spawn/encounter tables, cooked like everything else) + seeded procedural terrain/scatter inside them — plus hull/hardpoint configs, component/weapon definitions, stats schemas, factions. Audio ingestion deferred by default to the slice; the container supports it from day one.
14. **Blender authoring pipeline (user decision; validated by PoC 2026-11-06, `docs/tests/blender/report.md` in this repo).** Blender is the DCC for all models; engine never touches `.blend` — the hand-off file is an exported `.glb`. Run Blender itself headless (`blender --background --python`) for batch export/validation inside the cook pipeline (PoC proved build+export+EEVEE render work with no display). Export conventions baked into the cooklet, each verified by the PoC: **export settings** `export_extras=True`, default Y-up kept (engine axes *are* Y-up per decision #34 — the cooklet pass-throughs and asserts the glTF Y-up invariant; never trust the DCC's export up-axis setting); **content keys off node names**, not mesh names (mesh data blocks export as `Cylinder.001` junk); **hardpoint sockets = empties** — mesh-less named nodes (`hp_*`) parented in the hull tree, with per-socket custom properties arriving as node `extras` — a hull `.glb` self-describes its sockets, no sidecar file; hull-level metadata (class, mass) rides root-node `extras`; **cooklet owns renderer flags** — ignore the exporter's blanket `doubleSided: true`, fold `KHR_materials_emissive_strength` into the cooked emissive factor, **bake MikkTSpace tangents at cook time** (glTF ships POSITION/NORMAL/TEXCOORD_0 only), no triangulation needed (exporter emits triangles only); **exports are deterministic** — byte-identical GLB across Blender processes (verified by hash), so the two-cooks golden gate holds upstream; buffer compression is the cooklet's job (no Draco/Meshopt by default).
15. **UI/UX spec (user decisions 2026-11-06).** Engine side — primitives only, no game concepts: immediate-mode debug UI (Phase 3; ancestor of all editors), **world-space canvas** for in-world panels, **cooked text** (font atlas baked by the cooklet via stb_truetype — runtime draws glyph runs, zero font parsing), action-based input end-to-end (UI consumes actions, GLFW binds + OpenXR bindings map to the same names — every panel works with mouse/gamepad/controllers, no per-device UI code), UI as a render pass onto the Presenter's target list (no backbuffer, one desktop/VR path). Game side — **(a) one shared cockpit** for desktop and VR: same dash, same world-space canvas panels, one asset serving both modes — desktop may composite a light screen-space layer (reticle, target bracket) the VR presenter skips; **(b) desktop default = cockpit view**, external cam on toggle; **(c) diegetic 3D hangar** for loadout/ship design: walk around the ship, UI on screens in the space (scales unchanged to VR; the Phase 11 loadout editor's game-side twin — headless data model, two front-ends). UX rules that fall out of pinned systems: **assists always visibly offered** — level/stabilizer/air-brake/autopilot/targeting are named dash toggles with stat-scaled quality readout, never silent defaults (decision #12's assist state shows as a lit switch); **components go dark, they don't die** — component-offline (decision #12) renders as dead instruments on the dash, dock repair lights them back up; **what the player sees, the AI sees** — AI pilots read the same cooked stats and action interface, no human-only info channel.
16. **Editor doctrine (user decisions 2026-11-06).** All dev editors are **panels inside the running game/engine** — the one debug-UI tool (its widget layer built in Phase 3) summoned over any scene; no standalone editor executables, no second rendering stack. **Write-back rule: editors may only change human-editable source (TOML defs, etc.), never cooked artifacts** — watch-mode cooklet (Phase 0) closes the edit→see loop, git is the undo. The **replay scrubber is a formal deliverable** (Phase 6): headless replay stepping (Tier 1) + scrubber panel. Map authoring stays **viewer + live def tweaker** (Phase 8) — placement lives in text defs + coordinates, no full map-editor GUI. Model editing is Blender's job (decision #14); no node-graph material editor. Roster: cooklet CLI (P0) · manifest/asset browser + ECS/stats inspector (P3+) · **replay scrubber (P6)** · **map def tweaker (P8)** · **loadout editor panel (P11)** — the dev twin of the diegetic hangar (decision #15) on the same headless data model · keyframe editor + mod browser (P12).
17. **Planets & moons (user decisions 2026-11-06).** A moon is just another body def — same struct, smaller radius, weaker well, usually no atmosphere; no new systems. **(a) All major bodies move, from day one: authored kinematic rails.** Every body's position is an analytic function of sim time in its def (`orbit: <parent>, period, radius, phase`) — not simulated, so it's free: evaluable at any tick (replay scrubber, ghost-sim, time compression), zero drift, deterministic; the gravity well rides with the body. Rails make moonrise/moonset real and make moving-well integration a Phase 4 problem, not a Phase 8 surprise. **(b) 'Down' resolves via dominant home-well + crossfade blend bands:** each ship/round carries one home well (deterministic selection rule + hysteresis on switch); inside overlap shells between two wells' fields, the acceleration is a smooth crossfade — nested systems (moon inside a planet's well) are the design case, and "stand on the moon, down = the moon, not the giant in its sky" is a done-when test, not a hope. **(c) slice world = 2 planets + 1 moon + 1 station** — the moon proves nested wells + landing on an airless body. **(d) terrain art direction is a Phase 8 spike** (throwaway demo: stylized low-poly PBR + palette cards vs realistic-leaning) — the seeded-procedural pipeline doesn't care which, so decide with pixels in hand, not on paper. Gas giants, if ever: visual shell + no-fly authored volume, never a surface to land on.
18. **Crew & stations (user decisions 2026-11-06).** A **station is a component**: pilot/gunner/engineer/etc. seats mount on hull `hp_*` sockets like engines and guns — health (dark-not-dead), stats, role tags (`station.pilot`, `station.gunner`). **Occupancy is the mechanic**: sitting attaches the occupant's `StatsSet` to the ship as a source-tagged modifier stack (decision #11's "seat" source); standing, being knocked out, or the seat going dark drops the whole stack as a unit. `core/` knows only "occupancy" + "attached modifier source" — what a *Gunner* means is cooked `game/` data. Player and NPC crew run the identical code path. **(a) Dead until manned:** turrets, repairs, navigation, and trading functions do not run with an empty seat — no pilot-fallback degraded mode. Fixed forward weapons stay pilot-operated via the targeting computer (decision #12 unchanged); turrets and ship services are crew-gated, which makes crew hiring matter in combat. **(b) Walkable interior (supersedes cockpit-locked comfort):** the player can leave the seat and move through the ship interior — authored interior mesh + collision riding the ship transform (ship-local frame, not per-body physics), stations reachable on foot. This *replaces* the Phase 10 "cockpit-locked view" comfort line; VR comfort lives in interior locomotion options instead (smooth stick locomotion, snap/smooth turn, seated roomscale + handrail-grab mode — safe because interiors are ship-scale, not world-scale). **(c) Slice crew roster = full merchant crew:** pilot, gunner, engineer, navigator, trader — five role stations, hiring/assignment/XP-per-role in the diegetic hangar, all cooked defs + the same stats framework. **(d) Crew take damage:** a hit on a manned station rolls onto the occupant as status effects on their StatsSet (knocked out / injured) — seat stack drops, recovery over time or at a medbay/station. Crew death is not in the slice; injury/KO carries the stakes.
19. **Life support, sections, power, EVA (user decisions 2026-11-06).** **(a) Sectioned atmosphere:** hulls carry an authored **section map** (sections, `door` components between them, one air reservoir each). The reservoir is a new small **core primitive**: a state variable integrated per fixed sim tick from aggregated attributes (supply − load − leak), with threshold events — concept-free machinery; the word "oxygen" is cooked `game/` data. Doors isolate sections, engineers patch breaches, the walkable interior (#18b) means you physically walk to the problem. **(b) No survival clock:** life support is a **load check** — scrubber capacity vs crew count rides the modifier stack as a number; atmosphere state only *matters* when something breaks. No food/water/day counters, no resupply treadmill. **(c) Two-tier breach:** weapon hit on a sectioned hull → **small breach**: that section vents (reservoir drain + `atmo.venting` tag), crew in it get the #18d KO/injury path, closing doors isolates it, engineer (or the player, on foot) runs the patch repair task. **Hull breach stays the dramatic whole-ship destruction threshold** (#12 unchanged) — it is now *dramatic* precisely because sections exist: a hull breach overwhelms the whole system, small ones don't. **(d) EVA is in scope:** `airlock` is a component; a suited entity carries its **own reservoir** (same primitive); surface traversal uses the existing well field (the nested-well/moon decisions just made the surface a real place) + low-thrust assist-governed jets. Slice showcase: a suited moonwalk on the airless moon — `down` = moon at human scale, the #17b test experienced from boots. Atmosphere worlds allow EVA only inside authored suit-OK zones; nothing unauthored can hurt or allow you. **(e) Power pool becomes real:** reactors declare `power.supply`, life support + shields declare `power.draw` as attribute keys **in Phase 5 already** (so Phase 6's aggregation covers them), and the pool is one aggregate pair — supply vs draw, overload drops systems by priority (dark-not-dead again). Loadout tension: guns, shields, and air all compete for the same reactor. **(f) Comfort/scope honesty (Phase 10):** EVA reintroduces world-scale locomotion in VR — mitigations: EVA speed is low and assist-governed, suit HUD is the only panel, seated roomscale mode stays at the airlock; this is the one deliberate exception to the interior-scaled comfort rule, so its comfort options are Phase 10 done-when items, not hopes.
20. **Economy, trade, missions (user decisions 2026-11-06).** **(a) The full trade loop is core gameplay:** commodities are cooked data; **market nodes** sit at the station and at one authored planetary **outpost** (a landing-pad cluster with a terminal — supersedes #17c's station-only slice world, not a second station); `cargo hold` is a component (capacity attributes, commodity-type gates) and each ship carries a small **cargo manifest** (commodity stacks + owned-but-unmounted spare gear) — the only possession-side concept added. The trader seat (#18) pays off through price/discovery modifiers on its stack. **(b) Dynamic supply/demand — markets are sim state:** a market's per-commodity stock is an instance of the #19e **reservoir primitive** (supply = production + NPC flow along authored trade lanes, offtake = NPC and player purchases); **price is a derived attribute of stock level** via authored curves — never stored, so the scrubber and ghost-sim evaluate it at any tick like body rails. Every flow is a fixed-tick sim event in ordered containers: market state hashes into replay with everything else. Emergent *and* replayable is the cost of this choice; that construction is how it gets paid. **(c) Reputation is a stat:** per-faction reputation is an attribute on the faction's StatsSet; player actions post instant effects to it; threshold crossings flip faction tags (`faction.hostile` ↔ `faction.friendly`) using the same threshold machinery as reservoirs — AI aggression and market access read only tags. **(d) Runtime mission director, game-side:** reads only aggregate signals (reputation tags, market scarcity bands, player activity counters) plus a **seeded RNG stream keyed on (world seed, tick)** — the exact #18d pattern — and spawns missions from authored templates (bounty, patrol, escort, delivery, interdiction) targeted at regions/stations; a job is a tag/effect state machine with transactional rewards. The slice's hostile NPC is a director-spawned bounty. **(e) Slice grows accordingly:** 2 factions (merchant + hostile), a handful of commodities, 2 market nodes, one director bounty chain — "buy one better gun" is now funded by trade runs and bounties, not hand-waved.
21. **Thruster parts + propellant (user decisions 2026-11-06).** **(a) Thrust comes from thruster parts, in two classes:** `thruster.main` — main drives, big Δv along the socket axis, gimballed (Phase 5); `thruster.rcs` — small maneuvering pods on nose/tail/side sockets giving **translation (strafe) + attitude torque**, replacing "optional RCS" with a real loadout dimension. Hull sockets are **categorized** (main / rcs / gun / utility — authored in the `hp_*` node names + `extras` per decision #14), so pods cost sockets, mass, power, and propellant: literal loadout tension. **(b) Thrusters have stats like everything else:** each thruster part carries a `StatsSet` with attribute keys declared in Phase 5 — `thrust.force`, `thrust.isp` (efficiency: propellant flow per newton-second), `power.draw`, mass — aggregated by Phase 6 exactly like pilots/NPCs/weapons; part quality tiers are just better base stats. Dark-not-dead applies: a hit-throttled main loses thrust through the offline function-zero modifier, and pilot/engineer seat stacks feed response and tuning through the same pipeline. **(c) Propellant is a consumable and a trade commodity:** the `fuel tank` is a component with capacity attributes; ship propellant is another instance of the **#19e reservoir**, drained per tick as `force · dt / Isp` (hand-computable burn) and refilled at market nodes. Empty tank throws `propellant.empty` → thrust function-zeroed by tag — dark-not-dead again — and determinism is by construction: drain is a pure function of applied impulse at the tick. **(d) Economy mesh:** `fuel` is a bulk commodity on the trade lanes — a real market demand signal and the classic low-margin haul — and cruise range is a propellant budget, which gives trade-route planning teeth. **(e) Slice:** one fuel tank; a station→planet→station loop burns a modest % of the tank; hostile NPCs carry propellant and burn it under stabilizer use like everyone else — no AI free-flight cheat.
22. **Real system scale + FTL warp (user decisions 2026-11-07).** **(a) System defs go real-scale:** real planet radii (Earth-class = 6,371 km) and real AU-class separations between bodies. What stays arcade is the well machinery: bodies carry authored *well* params — well radius as a multiple of body radius (~10–100×), sized per system so the moon testbed (#17b) still nests inside its parent's well. The well/crossfade math doesn't change; only the numbers scale up. **Time compression is demoted** from travel mechanism to a tool: scrubber, rail visualization, tactical pause. **(b) Continuous warp — one space, one integrator:** `drive.ftl` multiplies ship velocity via an aggregated stat; determinism rides the swept-contact primitives, because a tick step at warp is 10⁶+ km — contact resolution is sweep-all-the-time at those speeds. No new space layer, no hyperspace, no gates, no second medium to render/stream/test. **(c) Safe-speed bubbles:** each body def authors `safe_speed` + bubble radius (≥ well radius); warp won't spool inside a bubble, and crossing a bubble edge at warp = forced decel + impact damage — swept, deterministic, testable. The bubble rides the same home-well math the wells already use. **(d) The FTL drive is a component with stats (#21b pattern):** attribute keys `ftl.speed_mult`, `ftl.spool_s` (wind-up, interruptible), `ftl.flow` (propellant per warp-second, drained through the #19e reservoir) — so warp range is still a propellant budget: tanker economy, fuel demand, and trade-lane math carry over untouched. **(e) Slice world at real scale:** every leg is a warp leg — undock, sublight climb out of the safe bubble, spool, warp, exit the target's bubble in orbit, descend to dock or pad; the slice loop's propellant stays a modest % of the tank.
23. **Docking (user decisions 2026-11-07).** **(a) Magnetic-clamp capture — docking is a physics state, not a menu:** station defs author `dock.port` targets (visual guide + capture zone, same Phase 7 capture-zone machinery as landing pads); approach inside the port's zone below `safe_speed` and the clamp engages — a **rigid constraint** binds ship↔port, alignment assist included, no delicate manual berthing. Undocking releases the constraint and push-off thrusters take it from there. Deterministic by construction: engagement is a swept-contact event at a fixed tick. **(b) Dock gear is a component (the #21 pattern):** ships carry a `dock.port` component on a utility socket (clamp strength, mass; dark-not-dead applies — a destroyed clamp won't engage); stations carry ports from their authored defs. **Docked is the one physical state that opens the suite**: dock repair (#12), propellant refill (#21c), trade terminal access (#20a), crew rotation, and the diegetic hangar/loadout screen (#15) all key off the clamped constraint — no separate "docked menu mode." **(c) The airlock mates — you walk over:** the ship's `airlock` component (#19d) joins to the station section it clamps beside; boarding and off-footing are *walked* through the mated junction under the sectioned-atmosphere rules (junction holds pressure; a breached junction is just a venting section). Never-teleport stays intact: cockpit → airlock → station interior → trade counter is one continuous walk in both modes, desktop and VR. **(d) Slice:** the game starts physically clamped at the station port; the trade run ends clamped at the outpost, and the walk to its counter starts through your own airlock.
24. **Ship & station building (user decisions 2026-11-07).** **(a) One build model at both scales: a station is a big inert hull with sockets.** Station defs reuse the Phase 5 loadout schema exactly — dock ports, market counters, crew stations, sections/doors/airlocks are components bolted onto categorized sockets (decisions #23/#18/#19 already implied this; now it's law). The engine has **zero station-specific structure**: a station is a ship-scale loadout entity pinned to a rail, built through the same content pipeline as hulls. **(b) Stations grow in-world — runtime assembly, authored-driven:** authored **build plans** schedule prefab modules delivered by construction tenders; the module is flown to a free socket and clamped on using the #23 clamp machinery, and station composition changes mid-play. Fully deterministic by construction: build steps are fixed-tick sim events driven by authored timelines + lane state through the same seeded-RNG pattern as #20d — growth replays and hashes like everything else. Player-side, ships-only in the slice; this machinery belongs to the world side (Phase 8), and station ownership post-slice inherits it for free. **(c) Player ship building = the diegetic hangar while docked (#15/#23b):** hulls and components are stocked at market nodes, purchases land in the cargo manifest, and assembly/bolt-on happens in the hangar — which is the same loadout data model the dev-UI loadout editor (#16) drives. **(d) Each hull is its own entity:** mounted components belong to their hull; swapping hulls is a **whole-ship swap** — the old ship sells/trades as a unit with its kit, the new hull arrives with its own. Upgrades happen by buying new parts (spares in the manifest per #20a, mounted in the hangar), not by uninstall-and-transfer; no salvage-stripping nuance in the slice.
25. **Factions (user decisions 2026-11-07).** **(a) Ownership is a tag:** stations, outposts, their dock ports and counters, and every NPC ship carry an authored `owner.<faction>` tag; market access, refuel, repair, and hangar services read **owner tag × your reputation tag** with that faction — hostile means your own customers won't serve you. No new machinery: it's the decided "everything reads tags, never the number" principle with the ownership tag made explicit. **(b) Faction-vs-faction stance is authored, not simulated:** faction defs carry stance tags (`stance.hostile.<faction>`), and NPC target selection (Phase 9 FSMs) reads **owner × stance × reputation** — hostile-faction interdictors engage merchant convoys as legitimately as they engage you. The player's reputation stays the only *simulated* inter-faction relation in the slice; full faction war (fronts, territory, faction↔faction reputation matrices) is explicitly **roadmap, not slice**. **(c) Faction power is a reservoir:** each faction has a `faction.power` instance of the #19e primitive — supply = production + held lanes + completed jobs, load = NPC losses + contested lanes; scarcity bands are threshold tags (`faction.pressure.high` etc.). The mission director reads power bands to size what it spawns — patrol strength, convoy escorts, raid/blockade chains — so ignoring the hostile faction escalates it and pushing back degrades it, all fixed-tick and replay-hashed. **(d) Slice:** station + outpost are merchant-owned; the hostile faction runs one authored pressure chain on the trade lane — the director's bounty is a link in it — and a power-band flip spawns merchant escort convoys; service cutoff on hostility is a scripted test moment.
26. **Ship wiring & internal interfaces (user decisions 2026-11-07).** **(a) Wires are authored physical components:** the hull def declares a **wiring net** — every wire is an individual def entry (two endpoint refs: sockets/components/junctions; type `power` | `signal` | `power+signal`; health; optional capacity), and junctions/panels are socket-mounted components where wires meet. The cooklet validates endpoint cross-refs at cook time like every other reference. The graph stays small by construction: one net per hull, tens of edges — per-component, not per-gadget. **(b) Power and signal are reachability facts:** a component contributes and functions only with a powered path from a source (reactor/battery → wires → consumer); controlled functions additionally need signal paths — fire-control solutions reach guns over signal wires, seat→turret authority likewise, sensor feeds route the same way. Reachability is recomputed **only on topology-change events** (destroy/repair/mount/unmount) in deterministic BFS order, never per-frame; ungated components drop out through the standard function-zero modifier machinery. **(c) Dark-not-dead composes:** destroying a wire or junction cascades a downstream dark set — same modifier stack, zero new state kinds; power overload shedding (#19e) picks victims by authored priority across the same graph. Air stays the sectioned #19 primitive — atmosphere is not wiring. **(d) Authored wiring + field repair:** hull defs ship default nets; the slice's player interaction is **replacing destroyed wire/junction parts from cargo-manifest spares** — an engineer-seat or on-foot activity, and part of dock repair. A hangar rewire panel (player re-routing branches for tradeoffs) is explicitly roadmap, not slice. **(e) Interface law:** the net refines only the ship's *internals* — the outward seams stay exactly four, all read-only to consumers: physics (aggregated body params + socket force points + #23 constraints), AI (identical aggregates/tags/controllers), UI/XR (change-event bus subscriptions), game systems (read tags + reservoir bands, write effects). Components never call each other — reachability, modifier stacks, and the effect bus are the only wires.
27. **NPC navigation & pathfinding (user decisions 2026-11-07).** **(a) System routing is an authored nav graph:** the map def extends the #20 trade lanes into a **nav graph** — waypoint/lane nodes (station & outpost anchors, patrol-area anchors, warp lane endpoints) and typed edges (lane / local / patrol). Route selection is a deterministic A\* over that graph (ordered containers, id tie-breaks, keyed on world seed + tick); **NPC warp legs are planned only endpoint→endpoint outside safe bubbles** (#22b) and executed with the exact same spool/cruise/decel machinery as the player. The graph decides *where*; the same assist controllers fly every leg through the same physics (#26e) — no spline authority, no teleport. Routes recompute **on events** (spawn, director retask, blocked node, target drifted beyond tolerance), never per tick. Construction tenders and delivery templates ride the same graph; their final approach is the #24b/#23 goal-seek onto the socket. **(b) Local avoidance is cheap and shared:** bodies are handled by the #22 safe bubbles (hard no-go for the warp planner, soft deflection on approach); ships add a radius-repulsion **separation term** to the assist/autopilot steering output — the identical term available to the player's autopilot assists, so AI has no privileged avoidance. Neighbor iteration is ordered, so deflections replay exactly. **(c) Interiors walk on the section graph for free:** the #19a authored section map — sections as nodes, doors/airlocks as edges, seats/counters/port/berth anchors as in-section goals — **is** the walk graph; no navmesh, no baked data. NPC walkers (boarders heading to their seat, merchants behind counters, dockhands) local-steer within a section and traverse a door as a fixed-tick event; they read #19 band tags, so a venting section is authored-avoided. Suited EVA movement reuses the same goal-seek for short hops. **(d) Determinism gates:** a scripted convoy runs its hand-computed node sequence and arrives at known ticks with matching replay hash; a blocked-node retask fires at an exact tick; two NPC ships on crossing lanes deflect with min-distance > sum of radii, identically on replay; and a hired crew member boards, walks the section graph airlock→gunner seat, and seats at a known tick — all headless, all in the state hash.

28. **Interactables — how anything gets "used" (user decisions 2026-11-07).** **(a) Interaction is a capability, not a component kind:** components and sockets that can be used carry authored **interaction facets** — action tags (`use.seat`, `door.toggle`, `repair.target`, `trade.counter`, `mount.socket`, `port.undock`, …) plus an `interact.range` attribute, declared in hull/station defs and cooked like everything else. No new entity type; `core/` stays concept-free; the cooklet rejects unknown action tags and dangling `repair.target` refs. **(b) One verb, resolved by tags:** the #15 input seam fires a generic `interact` action; a game-side interaction system gathers candidates by proximity to the prober (same spatial index hits use), gates validity purely on aggregate attributes/tags (seat stack free, `owner.×stance×reputation` at counters, suit present, section air/power bands), and executes as a **fixed-tick sim event** on the effect bus — seat attach/drop (#18), door/airlock state (#19a), wire/junction swap (#26d), trade leg (#20), clamp release (#23). Every interaction replays and hashes; UI still never calls a component (#26e unchanged). **(c) Dark sections:** a powered/signal-reachable panel gates powered interactables (same reachability fact as #26b), but **doors and airlocks carry authored manual fallbacks** always workable by hand — the fallback is its own declared facet, so a dark ship never traps anyone. **(d) In-world only:** every player verb is walked-and-touched — trade, loadout, repair, crew, dock/undock (#23d generalized; no non-diegetic player menu; status displays stay passive dash reads). Prompts are presentation only: in-range+valid highlight plus invalidity *reason*, both derived from the same tag snapshot; VR point+pinch and desktop aim+key fire the identical action. NPCs fire the **same events** via walk-graph arrival (#27c) — the interaction system is the single seam between intent and world state.

29. **Planetary terrain (user decisions 2026-11-07).** **(a) Terrain is an analytic function, not data:** `height = f(map seed, per-body relief params, surface position)` — hand-rolled multi-octave value noise over the sphere in cubic-face coords (no pole singularities). Cooked payload = the **generator params** (seed, octave/amplitude bands, feature strengths, biome palette table), never a terrain mesh; display meshes are generated/streamed on demand at any LOD. Zero baked terrain = infinite detail, tiny cooked units, and determinism by construction — the moonwalk replays to hash because terrain is arithmetic. **(b) One sampler, everywhere:** a single shared **height+normal query** in the active body's local tangent frame (fp64 offset from body center; the home-well #17b defines up) backs landing contacts (Phase 7), on-foot EVA walk (#19d), shell terrain impacts (Phase 9), and streamed mesh generation (Phase 8) — the renderer and the sim cannot disagree because they call the same pure function. **(c) Authored stamps bend the field:** map-def POIs (outposts, landing pads, landmarks) carry coords + **flatten/crater/mesa stamps** (radius, level height, blend) applied before noise — outpost ground is authored-flat, pads are guaranteed level for snap-to-rest (#23c), and named features are stamps, not luck; scatter (rocks/boulders) is instanced from seed + authored density tables. Cooklet validates stamps (radius covers POI footprint; pad stamp normal ∥ well normal at placement). Tweaker edits stamps like any map data (#16). **(d) Biomes are presentation bands in the slice:** authored noise-threshold → material/palette table (color, roughness, scatter density); nothing mechanical reads them yet — mechanical biome tags (hazards, resources) stay post-slice. The art-direction spike (#17d) stands, now with a real terrain field to render.

30. **Ship/station interior authoring (user decisions 2026-11-07).** **(a) Interior art rides in the hull `.glb`:** authored in Blender as named node groups, extending #14's named-node/empty discipline — one unit per hull, everything keyed by name; named empties mark **door frames, seat mounts, panel faces, counters, berth positions**, so every "walk up and use it" (#28) points at a real place in the art. **(b) The def's section map stays the sim authority** (#19a unchanged; `core/` never parses art at runtime): the cooklet validates art against the def — every socket/seat/door/canvas/counter sits in **exactly one** section volume, art door empties match the walk graph's door edges (#27c), and mated-airlock seams (#23c) align within tolerance; a mis-pair **fails the cook** like any dangling reference. **(c) Dash panels are panel components** (#26): canvas quads hang off the panel's mount transform — the same world-space canvases of #15, drawing only aggregate stats/tags snapshots (#26e); no new UI concept. **(d) Slice interiors are authored but minimal:** ship = cockpit + sectioned corridor + airlock + berths; station = dock ring + counter room; outpost = single market hall — enough that the #23c walkover is one continuous walked path, desktop and VR. Stations/outposts are hulls-with-interiors too (#24a) — same schema, no special case.

31. **Hull classes, sensors & contact display (user decisions 2026-11-07).** **(a) Hull class is a tag, not a cage:** each hull def carries a `class.*` tag (`shuttle` / `fighter` / `light_freighter` / `freighter` / `tanker` / `tender` / `station`) and its socket count is ordinary def data — the mockup ladder (4/8/12/18/20/24 sockets, station modular) is *art direction* for designing new hulls, not a cooklet-enforced rule. Downstream readers of the class tag: sensor icon resolution (#31c), NPC spawn tables (#25/#27), market price hints. **(b) Sensors are components; the contact picture is sim state:** a `sensor.*` component on a utility socket carries `sensor.range` and `sensor.res_arcmin` (angular resolution). Per fixed tick, each sensor produces **bounded-error measurements** of entities within `sensor.range`: resolution becomes an angular error cone, so position uncertainty grows with distance — deterministic jitter drawn from the map-seed RNG stream keyed by (seed, tick, sensor, target), the director's pattern (#20d) again. The ship's **contact records** (last measurement, uncertainty radius, class/owner when resolved, tick stamp) are fixed-tick sim state: they replay and hash, and the player scope *and* the Combat AI FSMs (#9) read the same one picture — no separate AI truth. The targeting computer is an ordinary assist controller that buys uncertainty down. **(c) Resolution bands:** a class silhouette resolves once hull size clears distance × angular-resolution (hand-computable band boundaries — pure arithmetic); owner/IFF resolves inside the IFF band, color = `owner. × stance × reputation` snapshot (#25), same tags, no separate truth; below both bands, unknown ring. **(d) Ghosts:** with the sensor feed dark (#26b) or a contact lost, the display holds the last measurement + tick as a **ghost** with authored lifetime — fading is presentation; ghosts never update, never become targetable or interactable.

32. **Audio doctrine (user decisions 2026-11-07).** **(a) miniaudio is the sanctioned sixth dependency** (explicit user approval, this session; gets a `docs/CHEATS.md` line like every other cheat): the one place we don't hand-roll — device I/O and mixing come from miniaudio, everything above it (source management, positional math, event→sound mapping) is ours. Source content stays OGG through the same cooklet → **cooked PCM**; no codecs or text parsing at runtime, pipeline unchanged. **(b) Audio is a presentation-side event consumer:** it subscribes to the effect/change-event bus exactly like FX — events spawn positional sources; audio never reads or writes sim state, never affects the sim, and audio state lives **outside replay hashes** — determinism doctrine untouched. **(c) Positional + sectional hearing:** every sound has a world position or attaches to an entity/section, with distance attenuation; **ear positions come off the rig-of-eyes** (the Phase-1 camera rig) — desktop gets stereo, XR gets binaural for free, no separate audio rig concept. Where you stand is heard: your section, door open/shut state, and venting shape the sound field — the same #19/#30 section state the sim and screens already use. **(d) Slice is fully diegetic:** every sound is a physical source you could point at — drive hum from the thruster component, an alarm from the panel that flashes, impacts at the hit point on the hull. No non-diegetic music bed; music stays post-slice.

33. **Onboarding, failure & time control (user decisions 2026-11-07).** **(a) The tutorial is the opening contract chain:** authored contracts on the mission director's own machinery (#20d) — undock, bubble-flight with full assists, a first cargo run to the outpost, a first dock/landing, a first parts purchase at the counter — with crew chatter on panel canvases (#30c) doing the guiding. No tutorial overlays, no separate tutorial scenario, no tutorial-specific code: pure map-def / director-template content authored with the editors (#16). **(b) Minute one is full assists ON:** the toggles are physical dash switches (#15), and panels/crew suggest which assist to drop next at authored safe moments — mastering flight *is* turning assists off, and each drop persists as progression. **(c) Failure = rescue & insurance, with permadeath optional:** hull destroyed → wake at a friendly station, cargo gone, the **wreck stays in-world** as a salvageable entity, pay to reclaim or replace; crew KO not dead as before (#18d — still no crew death in the slice). **Permadeath is a per-run flag** set when the run starts: under it, hull destruction with the captain aboard ends the run and the save archives — no mid-run reloads. **(d) No pause; time compression is a component:** sim time is real time and the player never stops it (#28d), but a **Time Compression Device** — a `time.compress` component on a utility socket carrying a `time.max_mult` stat — lets the player dial up to its cap on a physical dash knob. It runs the *same* fixed-dt sim faster through wall-clock using the #22a machinery (assist autopilot + physics LOD): identical tick sequence, identical replay hash — determinism untouched, and the dev scrubber keeps the same primitive.

34. **World coordinate convention (user decision 2026-11-07).** **Right-handed, Y-up, −Z forward** (matches glTF and OpenXR natively). Consequences: cooked GLB data passes through **identity** — engine axes == glTF axes, so #14's "cooklet converts Y-up → engine axes" is a pass-through that still *asserts* the Y-up invariant rather than rotating; the OpenXR/XR path needs **no basis transform** anywhere; Phase 1 math (quaternion composition, angle sign conventions, projection builders) is built on this frame and pinned by a convention test (`+X` right, `+Y` up, `−Z` forward, right-handed: cross(X,Y)=Z).

35. **Gfx test-GPU policy (user decision 2026-11-07).** Automated gfx tests (ctest, Tier 2) run on **lavapipe** — forced via `VK_ICD_FILENAMES` in the gfx test fixture — for determinism and because the 3090 hosts the user's live inference workloads (do-not-disturb). Real-NVIDIA runs (3090, and the now-visible P5000 with 16 GB idle) are manual/dev-only via a device-override env (`VE_GPU` name substring). ctest stays green on any box with mesa-vulkan-drivers installed, no display, no NVIDIA.

36. **Desktop window milestone evidence (user decision 2026-11-07).** The dev box has no display at all, so "rotating triangle at stable 60fps" is evidenced by an **Xvfb + lavapipe capture run** on this box (script + captured frames + fps log committed as evidence); it proves the WSI/swapchain/resize machinery, not 3090 window performance — that gate is re-run by the user on real hardware whenever a display exists.

37. **Vulkan API floor (user decision 2026-11-07).** **Instance/device API level 1.3** — sync2, dynamic rendering, sub-groups are core there; 1.4 features used only opportunistically behind runtime checks. Loader on the dev box is 1.4; lavapipe and NVIDIA both support 1.3 fully. No pre-1.3 fallback code ever.

38. **Windows is a real support target (user decision 2026-11-07).** The game must run on Windows; the user will build and run Windows tests on their own Windows machine. Consequences: (a) `core/`, `gfx/`, `platform/` non-XR bits, and the cooklet stay **OS-neutral C++23** — no POSIX-only headers outside `platform/`, no Linux-only APIs in shared code; (b) windowing/input goes through GLFW (already the pinned dep) behind the platform seam; (c) the cooked format stays byte-deterministic and cross-platform-identical (already true); (d) test tiers adapt: **lavapipe stays the deterministic golden gate on Linux**, Windows runs the same ctest suite against a **real GPU** with the fuzzy golden harness (#35/#36 machinery) — strict byte-identical goldens are never asserted cross-vendor; (e) the Linux headless contract remains the merge gate; Windows goes green on the user's box, wired in when it comes online (bootstrap sibling + ctest run recorded there, later phase-task). Phase 2 code is written under rule (a) from box 2.2 onward. **Amended 2026-11-08 (user decision):** distribution shape for now is exactly **two native builds — Windows and Linux**; no browser/WASM build. Remote access via an engine-hosted webserver was discussed and **tabled** — the headless-sim-daemon / HTTP-WS ideas resurface with server/multiplayer work (decision #4's "runs on a server someday").

**The slice game loop (what "done" looks like):** Start docked at the one station, minute one of the opening contract chain (#33a/b). Take off, fly manual out of the safe-speed bubble, warp to a gravity-well region near a planet (one of two), fight or avoid one hostile NPC ship — a link in the hostile faction's lane pressure chain (#25c) — run one trade loop between the station and the planetary outpost, land on either planet or dock back at the station, buy one better gun at the diegetic loadout screen, and go again — optionally stepping off onto the moon for a suited walk. Two planets + one moon (nested-well testbed, real radii + AU-class separations, decision #22), one station + one outpost (the minimal trade route), ~25 components, 5 stats, 2 factions, 2 weapon types, a handful of commodities including fuel, one fuel tank + one FTL drive, wire + junction spares for a field-repair beat (#26d), and a five-crew merchant roster with a walkable, sectioned interior round out the slice content.

## Phase 4 — Arcade flight & gravity core, headless (3–4 weeks) ⭐ the soul of the project
- **Gravity wells:** each planet has a well radius; inside, a smooth down-field (constant near surface, tapering to zero at the well edge); outside, nothing. Ships coast ballistically between wells. Tune the blend so crossing the well edge is imperceptible — that blend *is* the feel of the game. **Bodies ride authored kinematic rails from day one** (decision #17a): each well's center is an analytic position function of sim time (`orbit: parent/period/radius/phase`), so wells move — the integrator must sample moving wells, and rails stay evaluable at any tick for replays/ghost-sim. **Home-well selection + crossfade blend bands** (decision #17b): each ship/round carries one dominant home well with a deterministic switch rule + hysteresis; overlapping wells crossfade smoothly in their overlap shell.
- **Newtonian flight integrator:** fixed-timestep semi-implicit Euler with substepping; forces = thrust + gravity + (later) aero. Deterministic replay; record-and-replay tests from day one.
- **Assist controllers** (toggleable, Elite-style): auto-level, stabilizer (kills rotation), air-brake (velocity-kill toward relative-velocity-zero), waypoint autopilot. All plain PD/PID controllers over the same physics — a *lot* of the game feel lives here, and it's all headless-testable.
- **Trajectory preview:** since there's no analytic conic, the nav preview is a low-precision forward roll of the actual sim (cheap fixed-step ghost sim). Rollout == sim within tolerance is a testable property, not a hope.
- **Done when:** headless tests show (a) a scripted figure-8 with assists on/off ends within tolerance, (b) ghost-sim preview matches live sim, (c) deterministic replay hashes match. (Pure Tier 1.)

## Phase 5 — The ship designer: hull + hardpoints (3–4 weeks)
- Hull = mesh + named hardpoint sockets — sockets come **from the hull `.glb` itself** (mesh-less `hp_*` nodes per decision #14; def file only adds/overrides and supplies stats), cooked to binary; hull mesh referenced by content ID. Sockets carry a **category** (`main`/`rcs`/`gun`/`utility` — node naming + `extras`), and components bolt on: engines (thrust/Isp/gimbal), wings (lift coefficient), cockpit, reactors, shields, cargo — stats all data. Weapon hardpoints (turrets, gun ports) come in Phase 9 using this same socket model; `dock.port` (clamp) and `airlock` are utility-socket components under decision #23, and station/door/airlock components mount by the same rule. **World stations reuse this exact loadout schema** — a station def is a static hull with sockets and bolted components, no separate station structure (decision #24a).
- **Thrusters and tanks are first-class parts** (decision #21): `thruster.main` mounts on main sockets (big Δv along the socket axis, gimballed), `thruster.rcs` pods mount on rcs sockets (strafe translation + attitude torque), and the `fuel tank` component supplies propellant capacity. Each declares its attribute keys here — `thrust.force`, `thrust.isp` (flow per newton-second), `power.draw`, mass — and derived numbers come from them, never from a special-case struct. The `drive.ftl` warp drive is declared here too (decision #22d): `ftl.speed_mult`, `ftl.spool_s`, `ftl.flow` (propellant per warp-second).
- Derived ship stats: mass, CoM, inertia tensor from mounted components; engines off-CoM produce real torque; gimbals + RCS pods carry attitude authority (decision #21a). **No part breaking, no staging** — forgiving by design.
- Component-derived numbers (thrust, turn authority, shield capacity…) are declared as *attribute keys* now so Phase 6's modifier framework can aggregate over them without touching this phase's code again.
- **Stations are components too** (decision #18): pilot/gunner/engineer/navigator/trader seats mount on hull sockets with health, stats, and role tags (`station.*`); an occupant slot attaches the sitter's stats as a ship-scoped modifier source (wired in Phase 6). Dead-until-manned: seat-empty gates turret/repair/nav/trade functions — pure tag check, testable headless.
- **Hulls are sectioned** (decision #19): the hull def carries an authored **section map** — named sections, `door` components between them, `airlock` components; life-support units and the reactor mount on ordinary sockets. Power attribute keys (`power.supply`, `power.draw`) are declared here like every other component number, so Phase 6's aggregation owns the pool. Interior meshes (decision #18b) are organized along the same section boundaries.
- **Interior empties ride the hull unit** (decision #30a/b): named door/seat/panel/counter empties in the hull `.glb` carry the physical placement of everything the def declares; the cooklet pairs empties ↔ def — an interactive sitting in two sections (or none), or an art door with no matching walk-graph edge, fails the cook.
- **Wiring nets are hull def content too** (decision #26a): the def carries an explicit wire list — individual wire entries (type `power` | `signal` | `power+signal`, health, optional capacity, endpoints by socket/component/junction ref) plus junction/panel components mounted on utility sockets. The cooklet validates every endpoint cross-ref; Phase 6's reachability machinery owns what flows.
- **Interaction facets are def content too** (decision #28a): usable sockets/components declare action tags + `interact.range` in the hull/station def; cooklet validates tags against the known set and cross-refs (a `repair.target` must name a real wire/junction id in the net).
- **Class tags and sensors are def content too** (decision #31a/b): hull defs carry a `class.*` tag (socket count stays authored per-hull — no class-enforced budget), and `sensor.*` components mount on utility sockets with `sensor.range` / `sensor.res_arcmin` attribute keys.
- **Cargo holds are components too** (decision #20a): capacity attributes + commodity-type gates; the ship's **cargo manifest** (commodity stacks + owned spare gear) is part of this same loadout data model, so the loadout editor and save/load both get it for free.
- The loadout editor (later, Phase 11) operates on exactly this data model — headless now, two front-ends later: the in-engine debug-UI panel (decision #16) and the diegetic hangar (decision #15).
- **Done when:** a headless test builds hull+2 engines+2 wings, asserts the CoM/inertia numbers, misaligns one engine, and a stabilizer PID holds attitude straight — printed to console.

## Phase 6 — RPG stats & modifier framework (2–3 weeks)
- **Engine machinery:** sparse `StatsSet` (tagged attribute → base + derived fp32), one component type shared by pilots, NPCs, and ships. No hardcoded stat names anywhere in `core/`.
- **Modifier stack:** every modifier carries a source (entity / mounted component / effect / seat), gameplay tags, and a stacking policy (replace / refresh / stack-N / exclusive). Deterministic ordered aggregation: **base → flat add → percent → multiplier → clamp**, with per-attribute clamp ranges. Self-modifying cycles and dependent-modifier chains are rejected by design, not debugged.
- **Gameplay tags:** hierarchical string tags (`pilot.stunned`, `ship.shields.down`, `faction.hostile`) as the universal glue for effects, conditions, AI queries, and UI.
- **Effects & conditions:** an effect is a timed/instant bundle of modifiers (buff/debuff/damage as one system); a condition is a tag gate. Damage/heal/shield-drain are all just effects — the combat vocabulary gets built here for free.
- **Crew ↔ ship linkage (decision #18):** seat occupancy attaches the occupant's whole stat-derived modifier stack to the ship as a unit — pilot `Piloting`-style stats scale assist authority and turn response; a gunner's feeds lead quality, an engineer's repair rate. Sitting/ejecting/KO/seat-dark attaches or drops the stack atomically, and swapping/ejecting crew recomputes cleanly. Mounted components use the identical linkage (Phase 5), so equipment, crew, buffs, and environmental effects are one pipeline. `core/` knows only "occupancy + source-tagged modifiers" — role semantics (`station.gunner` meaning *what*) are cooked `game/` data.
- **Reservoirs + power pool (decision #19e):** the one new primitive — a scalar state integrated per fixed tick from aggregated attributes (supply − load − leak), with threshold tags on cross. Cabin air rides it per hull section (suits are reservoirs on entities too, and ship propellant is one more — drained by applied impulse `force · dt / Isp`, #21c); the power pool is the same primitive read as supply-vs-draw, overload drops systems by authored priority via function-zero modifiers (dark-not-dead again). Deterministic by construction: deltas are pure functions of aggregated attributes at the tick.
- **Wiring reachability (decision #26):** power and signal flow are graph reachability over the hull def's authored wire net, recomputed only on topology-change events (wire/junction destroyed or repaired, component mounted/unmounted) in deterministic BFS order; components left unpowered or signal-starved drop out via the function-zero machinery — a cut wire cascades its downstream dark set exactly like an offline component does. Fire-control → guns, seat → turret authority, and sensor feeds all route over signal wires.
- **Interaction event rails (decision #28b):** the events every "use" runs on — seat attach/drop stacks (#18), door/airlock state flips (#19a), wire/junction swap (#26d) — exist as tick-stamped effect-bus events with hand-computed replay checks; the resolution layer that *selects* the target is game-side and later, but the event shapes land with Phase 6.
- **The economy rides these same rails (decision #20):** market stock per commodity is another reservoir instance (flows = NPC lane traffic + production + purchases), **price is a derived attribute of stock level** (authored curve, scarcity bands = threshold tags) so it evaluates at any tick without stored market state; **reputation is an attribute** on each faction's StatsSet, transactions are instant effects through the effect bus, and tag flips come from the same threshold machinery. No new engine machinery beyond #19 — the market is what a reservoir does when you point it at cargo. **Faction power (decision #25c)** is one more reservoir instance (supply = production + held lanes, load = losses + contested lanes) whose threshold tags size the mission director's output.
- **Change-event bus:** attribute-change notifications with deterministic (tick, insertion) ordering; stats state hashes into replay/multiplayer state.
- Dirty-flag propagation recalculation on read — never a per-frame full recompute.
- **Replay scrubber (formal deliverable, decision #16):** replays stored as fixed-step sim-state records; a **headless replay-stepping API** (load, step frame-by-frame, jump to tick — Tier 1: scrubbed-to-tick state hashes equal live-run hashes at the same ticks); the debug-UI scrubber panel wraps that API — timeline, entity/stat inspector, state diff between ticks.
- **Done when:** hand-computed aggregation suites (stack caps, exclusivity, clamp order) pass; a test proves a pilot-stat change measurably changes the Phase 4 flight model's numbers through the seat linkage; a test proves any seat's occupant stack (in/out/KO) attaches and drops atomically with the ship's aggregates returning exactly to baseline; a reservoir unit test drains/refills/throws threshold tags at hand-computed ticks, and a power-oversubscribe test drops the lowest-priority system first; a wiring test destroys a scripted junction and asserts the exact hand-computed downstream dark set at a known tick, then a repair-from-spare round trip restores baseline exactly, inside the same replay hash; a hand-computed burn test asserts a scripted burn drains the propellant reservoir exactly `force · t / Isp`, the empty tank throwing `propellant.empty` and function-zeroing thrust until a market refill restores it, all inside one replay hash; a scripted market test drives lane-flow + player transactions and asserts stock/price land on hand-computed values with a reputation nudge flipping a faction tag at a known tick, and a scripted faction-power drain/escalation flipping a `faction.pressure` band tag at hand-computed ticks (#25c); a scripted 10-min combat-style scenario replays with identical stats-state hash; the scrubber API can step that replay to any tick with matching hash. (Pure Tier 1.)

## Phase 7 — Atmosphere, landing, contacts (3–5 weeks)
- Arcade aero *inside wells only*: density altitude curve, hull/wing lift + drag coefficients, forgiving stall. Reentry is just high-speed aero + a heat *number* (a budget, not a simulation) — heat tolerance is an attribute, so per-hull and per-modifier variation comes free.
- Landed-body physics: rigid hull, contact points per leg/gear, simple penalty-based contacts (or hand-rolled sequential impulses — great learning). Gear squash, no gear breaking. Capture zones (landing pads) snap-to-rest for VR-friendly low-stress landings.
- **Docking = the same capture machinery on a station port (decision #23):** `dock.port` targets with capture zones; below-threshold approach triggers a swept-contact engagement at a fixed tick and binds ship↔port with a rigid constraint (alignment assist on); release + push-off to depart. Docked is one physics state that gates repair/refuel/trade/loadout — no parallel menu mode. The ship's airlock joins the station section for the walk-over (#23c).
- **Swept-collision primitives** (moving point/capsule vs oriented component bounds) land here as part of the contacts toolkit — Phase 9's ballistics hit tests depend on them existing and being tested.
- **Surface = the #29b shared sampler:** one analytic height+normal function in the body's local tangent frame backs landing contacts here — later the same function serves EVA walk, shell impacts, and streamed mesh gen.
- **Suited EVA on foot (decision #19d):** a suited entity is a small sim entity with its own air reservoir, riding the same home-well field (a person on the moon feels the moon — the nested-well case at human scale) with low-thrust assist-governed jets + surface-walk contacts from this phase's contact toolkit. Airlocks cycle (two-door state machine on door components). Atmosphere worlds gate EVA to authored suit-OK zones via tags. Headless tests: reservoir drain on surface, jet rollout == ship ghost-sim integrator, well-switch hysteresis at walking speed.
- **On-foot verbs are interaction events (decision #28):** a walking or EVA entity toggling a door/airlock fires the *same* bus event as seated crew — scripted test asserts identical world-state delta and tick stamp.
- **Done when:** a scripted takeoff → cruise → pad landing runs headless and lands inside tolerance every time, a scripted **dock → clamped-walk-check → undock round trip** on a station port binds/releases the rigid constraint at known ticks (#23), and the same flight is visible in the Phase 3 renderer; swept-vs-moving-target unit tests pass.

## Phase 8 — FTL warp, time compression, scale, streaming (3–4 weeks)
- **FTL warp (decision #22):** `drive.ftl` speed-multiplier inside the same integrator — spool-up, per-body authored **safe-speed bubbles** (warp blocked inside, bubble-edge crossing at warp = forced decel + impact damage), propellant drained per warp-second through the #19e reservoir. Real-scale system defs (real radii, AU separations): the swept-contact primitives from Phase 4 are load-bearing here — a warp tick is 10⁶+ km. Ghost-sim trajectory preview rolls out through warp legs.
- **Time compression, demoted to a tool (decision #22a):** 1×–1000×+ for the scrubber, rail visualization, and the diegetic Time Compression Device (#33d) — assisted autopilot + physics LOD, distant ships integrate at coarse fixed steps, near ships at full rate; bounded error is a test, not a vibe. Time-compressed tick ordering must stay deterministic through the stats event bus (Phase 6).
- Floating-origin rebasing, camera-relative rendering, depth precision fixes (reversed-Z float24 — re-verified against the VR asymmetric projections).
- **Maps (hybrid, decision #13):** authored system/planet definitions — well params, stations, POIs, landing pads, scatter tables — cooked like any asset; terrain + scatter generated from the map's seed within authored bounds — terrain is the #29 analytic sampler with cooked generator params + authored POI stamps (#29a/c), biome palette table is def data (#29d), zero baked terrain meshes. Planet as geosphere/quadtree chunks with morphing skirts; scatter via instancing. **Terrain spike first** (decision #17d): throwaway demo of both art directions (stylized low-poly PBR + palette cards vs realistic-leaning) before committing the surface look.
- **Nested moving wells under compression (decision #17):** rails + home-well crossfade at scale — a ship landing on a moon that itself orbits its planet must stay deterministic through 1000× LOD, and coarse-integrated distant ships must not fight well switches.
- **Map def tweaker (decision #16):** a debug-UI panel to fly/orbit a cooked system and edit its authored defs live (well params, POI/station placement by coordinates) — writes back the source def, watch-mode cook hot-swaps the cooked unit. No interactive paint GUI; placement stays in text defs.
- **Economic geography is map data (decision #20):** market nodes (station + outpost), authored **trade lanes** between them with baseline NPC flow rates, and per-node production rates are part of the system def — the tweaker edits these too, and the map's seed feeds the director's RNG stream (Phase 9/11), so a cooked map fully defines one deterministic economy. Market nodes, their ports/counters, and spawn tables carry **faction ownership tags** (`owner.<faction>`, decision #25a) alongside authored inter-faction stance (#25b).
- **Opening contract chain is map data too (decision #33a):** the tutorial jobs are authored director templates riding the same seeded director machinery (#20d) — the tweaker edits the chain like it edits lanes and markets; the slice's opening five jobs are the tutorial.
- **The nav graph is map data too (decision #27a):** waypoint/lane nodes (station & outpost anchors, patrol anchors, warp lane endpoints) and typed edges (lane / local / patrol) are authored in the system def right beside the trade lanes and edited by the tweaker; the cooklet validates node/edge cross-refs — a dangling edge ref fails the cook like every other bad reference.
- **Station build plans grow stations mid-play (decision #24b):** authored plans schedule prefab modules delivered by construction tenders — the tender flies the module to a free station socket and clamps it via the #23 machinery, station aggregate stats update, all as fixed-tick sim events (authored timelines + lane state through the seeded-RNG pattern), so growth replays and hashes. Station defs themselves are plain loadout entities (#24a) — no new structure, just scheduled bolt-ons. Each prefab module is itself a hull-with-interior unit (#30): its own section map + named empties, and its clamp seam's airlock pairing is cook-validated, so a station grown mid-play is walkable through its new rooms the tick it lands.
- **Terrain determinism is tested (decision #29):** hand-computed height+normal at fixed surface coords reproduces exactly; a pad stamp keeps the pad normal ∥ local well normal within tolerance at every rail tick; an EVA walk across a stamp blend stays continuous (no crack, no pop) inside the replay hash.
- **Done when:** a headless scripted **warp leg** (planet→planet at real separation: spool → cruise → deterministic safe-bubble crossing with forced decel + damage) finishes at exact fixed ticks with hand-computed propellant drain (`ftl.flow` × warp-seconds) and matching stats-hash; a headless planet-to-planet assisted cruise at 1000× compression still finishes within bounded error (scrubber tooling), and land + zoom to surface has no pops or Z-fighting — verified headless via fixed-pose golden images + frame-delta assertions; plus a scripted moon landing inside a planet's well keeps `down` = moon throughout (blend-band test), and a scripted **station build step** (tender clamps a prefab module onto a free socket at a known tick; aggregate station stats update, replay hash matches — #24b).

## Phase 9 — Combat: weapons, shields, damage (3–4 weeks)
- **Weapon components mount like everything else** (Phase 5 sockets): lasers/beams = instant-hit raycast vs component bounds; guns = spawn physical projectile entities (muzzle velocity inherited from the firing ship — drift cuts both ways); rockets = unguided but steerable-ish darts with a short boost. Damage/range/ROF/spread/heat are all attributes.
- **Projectiles are ordinary sim entities:** same fixed-step integrator, gravity-well affected, deterministic, time-compressible; the ghost-sim from Phase 4 doubles as the ballistic prediction backend.
- **Damage pipeline = Phase 6 effects:** hit → shield attribute drain → overflow to hit-component health → at zero, component goes OFFLINE via a function-zeroing modifier (engines stop thrusting, guns stop firing, shields stop regenerating — `ship.component.offline` tag) → dock repair restores health + removes the modifier. Whole-hull destruction only via a dramatic threshold (hull breach), not component pile-up. **Two-tier breach (decision #19c):** a hit on a sectioned hull wall also opens a *small breach* — that section's air reservoir vents (`atmo.venting` tag) until doors close or an engineer (NPC crew or the player, on foot) runs the patch repair; occupants in the section ride the #18d KO path. The whole-ship hull-breach threshold stays as-is — now dramatic because the section system exists. **Wires ride the same pipeline (decision #26):** damage rolls can sever wire runs and junctions inside the hit section — the downstream dark set cascades through the reachability machinery, and repair means replacing the part from cargo spares (engineer seat or on-foot), not a heal button.
- **Targeting computer = assist controller** (the Phase 4 pattern again): deflection solver for ballistic lead (analytic flat-space solve first, ghost-sim refine inside wells), range + closure + deflection readout, optional rocket designation assist. Pilot stats scale lock time / deflection quality. The assist's output is a *suggestion* — the assist-reticle test property is that firing on its solution actually hits a scripted evader.
- **Combat AI (slice scale):** one hostile faction, FSM pilots (patrol / engage / disengage / withdraw) that fly with the *same* assist controllers and stats the player uses — aggression, engagement range, and retreat thresholds read from attributes; kills/truces update faction reputation tags (decision #20c — per-faction reputation attributes; threshold crossings flip `faction.hostile` tags the FSM reads). Anything beyond local maneuvering routes over the #27a nav graph — patrol circuits, convoy legs, director retasks, and NPC warp legs planned endpoint→endpoint around safe bubbles — while steering carries the #27b radius-repulsion separation term, the exact one the player's autopilot assists get: AI flies the same physics with no privileged avoidance.
- **Director-spawned hostiles (decision #20d):** hostile NPC ships come from the **mission director** (game-side) instantiating authored templates (bounty, patrol, escort, delivery, interdiction) from aggregate signals — reputation tags, market scarcity bands, **faction power bands (#25c)**, activity counters — plus a seeded RNG stream keyed on (world seed, tick), the exact #18d pattern. NPC target selection also reads **authored stance tags** (#25b): interdictors engage merchant convoys as legitimately as they engage the player; power-band flips spawn merchant escort convoys. A headless test pins one seed and asserts the exact mission sequence the director spawns.
- **Crewed stations in combat (decision #18):** a turret only fires while its seat has an occupant — the enemy AI's gunner FSM is the same pattern as its pilot FSM, and the enemy's turret goes silent when you knock out its gunner (seat dark or occupant KO'd). Hits on manned stations roll onto the occupant as KO/injury effects (Phase 6 effect bundles) — deterministic per-hit input to a seeded roll, so it replays identically.
- **Contact map is shared sim state (decision #31b):** per-tick sensor measurements with bounded, seeded uncertainty (jitter keyed by seed+tick+sensor+target), class/IFF resolution bands (#31c), and bounded-lifetime non-targetable ghosts (#31d) — the player scope and the AI FSM read the *same* contact records, and the targeting computer lowers uncertainty as an assist controller. Tests: a seeded measurement sequence replays exactly; uncertainty grows with distance and shrinks under assist at authored ranges; a class band flips at hand-computed boundary ranges; ghosts never become targetable.
- **Done when:** (a) a scripted 1v1 duel replays with identical trajectory + stats hash, (b) assist-ON ballistic solution hits a scripted evader while assist-OFF straight-shot fire misses it — proves the lead math does real work, (c) shield-absorption overflow numbers match hand calc, (d) offline→dock-repair round-trip restores exact pre-combat stats, (e) an empty-seat turret does not fire and a KO'd gunner stops mid-duel, both inside the same replay hash, and (f) a scripted convoy runs its hand-computed nav-graph node sequence arriving at known ticks, a blocked-node retask fires at an exact tick, and two ships on crossing lanes deflect to min-distance > sum of radii, identically on replay (#27d). All Tier 1; tracers/impacts/reticle FX deferred to the slice + XR phases.

- **Binaural XR audio for free (decision #32c):** ear positions come off the XR rig-of-eyes into the same positional mixer — desktop stereo and VR binaural are one code path.
- **Action-based input** (grab, pinch, throttle, fire, menu, **interact** — #28b: one verb for every walked-and-touched use; VR point+pinch and desktop aim+key fire the identical action; bindings live in runtime profile JSON, not code) + haptics. Throttle/attitude on sticks, fire on trigger, assists (flight *and* targeting) as physical toggle switches on the cockpit panel — diegetic by default.

- Comfort design (decision #18b, supersedes cockpit-locked view): **walkable ship interior** — authored interior mesh + collision riding the ship transform, stations reachable on foot. Never teleport; assists remain the drift-sickness fix out the window. Interior movement is root-motion over authored collision in the ship's local frame. **EVA is the one deliberate world-scale exception (decision #19f):** low assist-governed speeds, suit HUD as only panel, seated roomscale mode at the airlock; these comfort modes are done-when items, tested through `xr_mock` like everything else.

## Phase 11 — The vertical slice (ongoing)
- Game loop: **diegetic 3D hangar** loadout (decision #15 — walk around the ship, pick hull, bolt on components incl. weapons on in-space screens) → launch (cockpit view default on desktop) → duel or dodge a director-spawned bounty (one hit severs a wire run — replace it from spares on foot, decision #26d) → a trade run station↔outpost → land on a planet or dock back → buy the better gun. Hull purchases at market nodes are **whole-ship swaps** — the new hull arrives with its own kit, the old ship sells as a unit (#24d). Two planets + one moon + one station + one outpost (nested-well testbed + minimal trade route, decisions #17c/#20a), ~25 components including weapons.
- **Trade & bounties play for real (decision #20, every leg walked-and-touched via #28d — stand at the counter, no trade menu):** the station and the planetary outpost run **live markets** — dynamic supply/demand from NPC lane flow + player transactions — and the director's jobs pay credits that fund gun and crew upgrades; the trader seat's price/discovery modifiers decide who shops well; reputation nudges flip faction tags and change what the director sends your way; **fuel** is the bulk commodity on the lanes, and both nodes refill your propellant reservoir (decision #21c). Both nodes are **merchant-owned (#25a)** — hostile merchant tags cut off your own refuel/repair/hangar as a scripted test moment — and the hostile faction runs one **power-reservoir pressure chain** on the lane, with the bounty a link in it and convoy escorts spawning on band flips (#25c/d). The trade terminal is a diegetic station-interior counter (decision #15) rendered as a world-space canvas, reached **on foot through your own mated airlock while clamped at the port** (decision #23c); the whole economy is replay-hash-stable.
- RPG layer plays: pilot XP/progression from flying, trading, and combat with the hostile faction from Phase 9 (its AI pilots already run on the same stats/effects/tags — no special AI stat path); reputation as gameplay tags; trade prices derived from trade-style attributes + faction tags. All stat *definitions* are `game/`-side cooked data — this phase proves the engine/content split was real.
- Diegetic cockpit panels (VR + desktop) render from the stats change-event bus: no polling, no duplicate state. Combat FX/tracers/impact flashes and the targeting reticle are presentation-side consumers of sim events.
- **Sensor scope is a dash canvas (decision #31):** the scope draws contact records — class silhouettes by resolution band, IFF colors from owner×stance×reputation, uncertainty rings, fading ghosts — same sim state the enemy FSM aims from; severing the sensor signal wire (#26b) is the scope's honesty test: last-known ghosts, then silence.
- **Audio (decision #32):** miniaudio (sanctioned dep, #32a) behind our own source layer; OGG cooked to PCM by the cooklet. Sounds spawn from effect-bus events only (#32b) — audio never touches sim state, sits outside replay hashes — and they're positional + sectional: you hear *from your ears* (rig-of-eyes), your section and door state shape the field (#32c). Slice stays fully diegetic: hum, alarms, impacts, all pointable to a source (#32d). Headless tests cover the mapping (event → correct source + gain math), not the waveform.
- Save/load via the cooked asset format: serialize ship loadout + crew stats + component health + sim state, reload, replay identical trajectory and stats hashes. A run carries its **#33c permadeath flag** from the start; under it the save archives at run end — no mid-run reloads.
- Editor tooling as natural byproduct: the loadout editor is an in-engine debug-UI panel (decision #16) — ECS + pick/drag + ghost previews — and it is the dev twin of the diegetic hangar, both front-ends on the Phase 5 data model.
- **Hire your crew (decision #18c):** in the diegetic hangar, fill the five merchant-crew stations — pilot, gunner, engineer, navigator, trader — from hired NPC defs (stats, price, personality tags); XP accrues per role, seats get assigned, and the whole roster rides the same Phase 6 framework. Unmanned station = dead function, so crew hiring is a real loadout decision, not flavor. Hired crew then *walk to their seats*: the #19a section map doubles as the walk graph (#27c) — boarders route airlock→berth→seat, station folk hold their counters, and venting sections are authored-avoided via the #19 band tags.
- **Interior:** the slice ship has a walkable interior (decisions #18b/#30d — authored minimal inside the hull `.glb`, empties validated against the def per #30b) organized as **sections with doors** (decision #19a): pilot seat + four station seats + airlock, all reachable on foot, dash/panels as world-space canvases (decision #15). Sections power the breach drama: the duel can open a small breach, and someone — you on foot, or the engineer — goes to close doors and patch. Desktop drives it with station-swap + cockpit cam; VR walks it (Phase 10 comfort set).
- **Moonwalk:** the slice's showcase quiet moment — suited EVA on the airless moon after landing (decisions #19d/#29b): the nested-well test felt from boots on the shared analytic terrain field — the ground underfoot and the ground on screen are literally the same function, with the planet hanging in the sky and `down` stubbornly = moon. Ride check: reservoir numbers, jet assist, and the walk all replay to hash.
- **Crew stakes:** station hits KO/injure occupants (decision #18d) — the duel from Phase 9's tests now includes your gunner going quiet until an engineer or time at a medbay restores them; no crew death in the slice.
- **Rescue & insurance (decision #33c):** if the hull dies, the captain wakes at a friendly station — cargo gone, the **wreck persists in-world** as a salvageable entity — and paying reclaims or replaces the ship. Tests: the wreck entity survives save/load, reclamation restores the loadout at the station, and the whole loss-and-recovery arc replays inside the hash; with the permadeath flag set instead, the same destruction archives the run.
- **Time Compression Device (decision #33d):** a `time.compress` component on a utility socket, dialed from a dash knob up to its `time.max_mult`; test: an 8× run produces the identical tick sequence and replay hash as 1× (only wall-clock differs), and there is **no pause** anywhere in the player's reach — #22a's autopilot/LOD machinery, now diegetic.
- **Done when:** you fly it with a keyboard **and** from the cockpit in VR, with a hostile NPC engaging you through the same stats machinery; your crewed turret answers and the enemy's goes silent when its gunner is KO'd — all through the one seat-occupancy path, with a hired gunner walking the section graph airlock→seat and seated at a known tick inside the replay hash (#27c) — while all its tests stay headless.

## Sequencing notes (why this order)
- Core-before-renderer (Phases 1/4 before 2/3, swap allowed): the flight/gravity core and assist controllers are the unique learning; rendering is commodity learning you can interleave. If Vulkan stalls for two weeks, jump to Phase 4 — you lose nothing and gain momentum.
- Stats framework (Phase 6) deliberately follows the ship designer (Phase 5): you aggregate stats you have already physically derived, so every Phase 6 test has real inputs instead of toy numbers.
- Combat (Phase 9) deliberately comes after stats (6), swept contacts (7), and time compression (8): damage is an effect, hit tests need the collision primitives, and duels under warp must already be deterministic. Nothing new to learn at combat time — it's pure composition, which is the payoff the engine/content split was built for.
- Arcade physics removes the astrodynamics cliff, but two hard problems remain and they come *after* something runs: well-edge blending for **nested, moving** wells (rails + crossfade, decision #17) + time-compressed physics LOD (Phase 8), and floating-origin/depth precision (Phase 8). Motivated, not abstract.
- **VR is ~free if the Presenter seam + rig/eyes cameras + off-axis projections land in Phases 1–3, and ~a rewrite if discovered in Phase 11.** That's why those constraints are written into the earlier phases' definitions of done, even though the XR phase is Phase 10.

## Standing rules
- Process rules for coding agents live in `AGENTS.md` at repo root (read it before any implementation work).
- One phase-task per commit, tests in the same commit.
- **Branching:** all work on `testing`; `main` gets a promotion only on the user's explicit request, and README.md is the only documentation on `main`.
- **Standalone project:** shares no code, assets, remotes, or repo with any other project.
- No subsystem ships without a headless test proving it; `ctest` green with no `$DISPLAY`, no headset.
- **XR API calls live only in `platform/xr/`** — everything else talks to the Presenter/action interfaces, so `xr_mock` covers CI.
- **Game concepts never enter `core/`** — if it names a game stat or weapon, it's `game/` code or cooked data.
- Validation layers + sanitizers (ASan/UBSan) on every test build; TSan when threading starts.
- Anything you "cheat" (Volk, GLFW, OpenXR loader, stb, miniaudio — #32a, user-approved) gets written in `docs/CHEATS.md` with why, so the from-scratch claim stays honest.
